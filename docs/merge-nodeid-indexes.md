# 0.1.10+mergeindex.1：单库追加的合并索引修复

上游 0.1.10 的合并临时库主键以 `job` 开头，但实例级导入核验按 `nodeid`
单独查询关系和阶段，导致每个测试反复扫描整个模块。百万条关系的模块
因此可能在串行核验中阻塞后续派发。

在已合并的可丢弃临时库上建立 `relations(nodeid)` 与 `phases(nodeid)`
索引，再执行原来的精确核验和导入。查询谓词、关系、别名、位置、来源、
测试归属、旧正向关系子集和完成实例保护逻辑全部不变；正式库 schema /2
不变。索引创建失败同样保留原始 capture 并阻止提交和清理。

回归对比索引前后的全部逻辑表、原有已完成实例、别名/位置/分片来源和
两个相同 nodeid、不同 job 的记录；另用 SQLite VM 指令量验证点查询成本
下降，覆盖正常清理与索引失败的回滚，不以墙钟耗时作断言。

正在运行的冻结实现不修改。现有堵塞只在其可丢弃临时库上加索引，逐表
指纹前后完全一致后提交；原始分片和正式库不作此索引操作。后续合并在
独立冻结目录使用本修复，已有 worker 保留原 PID/开始时间和真实数据目录。
完成实例不重跑，CUDA 队列继续排除 XPU 文件。
