# 0.1.12：僵尸进程退出判断与关系保留

发布日期：2026-10-30。

## 问题与修复

ARM64 昇腾实测中，测试已通过，但一个已退出、等待容器 PID 1 回收的进程仍处于
`Z` 状态。0.1.11 的 `settle` 仅检查 `/proc/PID` 是否存在，因而一直拒绝关系汇总；
热日志恢复也存在相同判断。僵尸进程已不能继续写入，其退出前提交的数据仍然有效。

0.1.12 为汇总、热日志恢复、压缩前检查和子进程等待统一进程存活判断：

- `Z` 状态或 PID 已消失：允许按原有流程校验已提交数据。
- 真实存活或状态不可确定：继续阻止恢复、汇总或删除原件。
- 子进程已有启动时间回执时继续核对 start ticks，保持 PID 复用保护；缺少身份信息时
  不将另一个存活 PID 擅自视为已退出。

按现有 SQLite、归属、API、别名、调用位置和来源校验汇总关系。原始缺口和缺少结束
回执的状态保留，不伪造结束回执，不恢复未提交观测，不将汇总成功解释为采集零遗漏。
`settle` 保留原目录，生成新目录，并记录实际汇总器版本。`compact` 仍只有在现有全部
数据核验通过后才执行原件清理。

本版本不处理容器 PID 1 为何没有回收进程，也不通过杀进程解决问题。采集身份规则、
存储格式、测试参数、设备选择、API 台账及调度策略保持。

## 验证

- Linux ARM64 / CPython 3.11：48 项定向回归通过；完整回归 194 项通过、9 项按原有
  标记跳过。真实子进程在写入关系后成为僵尸，验证关系和来源保留、缺失结束回执的
  gap 保留、原始文件不改写；另验证已提交热日志数据恢复和原始事故副本保留。
- 活进程拒绝、PID 复用、procfs 状态不可读或格式不完整均有回归覆盖。
- 昇腾 910B2 实机：3 个 NPU 小样本通过，18 条关系、8 个 API、0 个报告缺口，
  doctor、settle 和结构审计通过。
- 原始事故数据重汇总通过：249 条关系、254 条分片来源，其中原僵尸进程分片的
  21 条关系保留；233 个原始文件内容不变，2 条外部程序采集缺口继续保留。
- 完整验证记录见 [validation.json](validation/0.1.12.json) 及发布附件；这些结果不替代
  全量测试或任意硬件与工作负载的兼容性验证。

## 升级与重汇总

等待当前测试和真正存活的采集进程退出后安装新 wheel。不要在运行中的测试里替换包。
已有冻结 runtime 不改写，原始采集版本不追溯修改。

```bash
python -m pip install --no-deps ./api_test_relations-0.1.12-py3-none-any.whl
python -m api_test_relations settle --out ORIGINAL_RUN --destination NEW_RUN
```

目标必须是原目录外尚不存在的新目录。已提交关系可以重新汇总；没有原始证据的数据
不会凭升级恢复，原有采集缺口继续报告。
