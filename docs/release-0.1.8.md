# 0.1.8：保留父子进程的不同别名证据

0.1.7 将同一测试阶段的一个 API 限制为一条记录。父进程和子进程的别名或首个调用位置不同，合并时会覆盖其中一条；严格核验因此拒绝压缩或追加。串行入库也会触发，增加锁或减少并发不能解决。

0.1.8 将逻辑关联与具体证据分开。原始采集保留每个别名组的首个位置；汇总按完整证据去重并保留所有分片来源；压缩库保留同样的数据。增量库升级为 `/2`，保留旧观测和已完成测试，同时保存位置与进程来源。别名组不做跨进程并集，不放宽原始证据校验，不覆盖已完成测试。

## 升级

1. 停止派发新任务，等待在途采集结束；保留原始分片和旧数据库。
2. 安装 0.1.8 wheel；新采集使用新的输出目录。冻结过的运行快照必须重新准备，不能只更新安装目录。
3. 对旧原始分片使用 `settle --out OLD --destination NEW` 生成独立汇总并核验。该命令保留原件。
4. 增量 `append` 在事务内迁移 `/1` 到 `/2`，失败回滚；原有核验后清理规则保持不变。旧版写入器不能继续写 `/2`。

只有旧摘要、没有原始分片时，已经被覆盖的证据无法恢复；必须重新采集。升级不等于已证明历史采集无缺口。

## 验证

回归覆盖：父子别名不同、分片顺序交换、重复分片与重复合并、位置及来源保留、压缩前后逐行一致、旧汇总重建、增量迁移及事务回滚、4 个独立 pytest 进程各自启动真实子进程。

2026-10-27 在 Linux AArch64 / CPython 3.11 验证：

- 完整插件回归：87 通过，2 个既有真实 CUDA/torch 可选测试未启用。
- 原始 `TestSpinCli.test_test_passes_the_exit_code_through` 与 `TestSpinCli.test_test_runs_pytest`：2 通过。同一批原始证据在 0.1.7 合并后只剩 67 行且核验失败；0.1.8 保留 79 行、97 条来源并通过严格核验。实际压缩与增量迁移均通过，两个测试各自的两组 `manual_seed` 别名保持独立。
- 最终 wheel 与 `trace_api_chain` 同进程运行真实 NPU Dropout1d 用例：通过，73 条关系证据，关系和调用链均无报告缺口，原始分片核验与调用链回放入库成功。
- wheel 中所有 23 个包文件与候选源码及隔离安装逐字节核对。SHA256 见验证记录。

`spincli` 仍保留 2 条外部非 Python 进程未插桩缺口；没有将这些缺口清除或改记为完整覆盖。白名单全量测试未完成，本发布不将小样本验证冒充全量结果。详见 [结构化验证记录](validation/0.1.8.json)、[回归日志](validation/0.1.8-regression.log)、[spincli 日志](validation/0.1.8-spin-tests.log)。
