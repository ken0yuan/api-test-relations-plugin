# 0.1.11 生命周期审计重复开销修复

调用链插件与关系插件一起运行时，CPython 的对象内省会产生大量审计通知。旧关系插件的 Python `_audit` 会接收每个通知，对不属于生命周期控制的通知立即返回。在 CANN 初始化及大型对象图观察中，这些 Python 回调造成了显著重复开销。

新入口 `lifecycle_audit_filter(callback)` 是由普通 `sys.addaudithook` 持有的 C 调用对象。仅原有七种生命周期通知进入相同的 `_audit`：`sys.setprofile`、`sys.settrace`、`subprocess.Popen`、`os.fork`、`os.posix_spawn`、`os.exec`、`os.system`。它对事件名做完整 Unicode 比较，参数元组原样传入，拒绝异常保持传播；其他通知仍与旧处理器一样不产生任何证据或行为。

这不是减少 API 采集：API 目录、解析、调用观察、别名证据、测试阶段、子进程保护和关系库合并规则不变。不会以对象是否“相关”为由过滤实体。没有要求普通使用必须安装 trace-api-chain；可选联合回归继续默认跳过。

候选完整 API 回归 119 项通过、9 项跳过。还应以服务器原始 NPU 用例的实际双插件加载、测试回执、调用链图和 API 关系库绑定验证作为部署验收依据，不能仅凭单元测试声称全量任务完成。
